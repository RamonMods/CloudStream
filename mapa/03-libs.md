## Notas e evidências

- **Evidência de uso no app** (`gradle/libs.versions.toml` de `recloudstream/cloudstream`): `nicehttp = "0.4.18"` (`com.github.Blatzar:NiceHttp`), `torrentserver = "7861970"` (`com.github.recloudstream:torrentserver`), `media3 = "1.9.3"`. Ou seja, apenas **torrentserver** é consumido diretamente deste conjunto; NiceHttp é consumido do upstream.
- **Evidência de uso em extensões** (`build.gradle.kts` de `recloudstream/extensions`): `com.github.recloudstream.cloudstream:library:-SNAPSHOT`, `Blatzar:NiceHttp:0.4.11`, `jsoup:1.18.3`, `jackson-module-kotlin:2.13.1`, `teamnewpipe:NewPipeExtractor:v0.25.2`. Nenhum dos forks desta tabela é dependência declarada do repo de extensões.
- **Conclusão prática para um repo de extensões**: só faz sentido olhar `NewPipeExtractor` (use o upstream, não o fork de 2022), `NiceHttp` (use o upstream estável, salvo migração KMP) e, marginalmente, `UniFile`. Os demais são player/build/site/comunidade — não pertencem ao classpath de uma extensão.
- **Riscos de licença**: `NiceHttp`, `libass`, `media-ffmpeg`, `csredirect`, `cs-bot`, `discord-commands` não têm LICENSE próprio no repo. `cs-bot`/`csredirect`/`discord-commands` devem ser tratados como "sem licença" (uso restrito); `libass`/`media-ffmpeg` exigem atribuição das licenças upstream; `torrentserver` aplica GPL-3.0 por declaração no README.
